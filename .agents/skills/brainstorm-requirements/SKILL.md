# 요구사항 브레인스토밍 — 꼭 필요한 질문만

**원본 참고:** [Superpowers `brainstorming`](https://github.com/openai/plugins/blob/main/plugins/superpowers/skills/brainstorming/SKILL.md)에서 **맥락 확인 → 질문 → 대안 비교 → 설계 확인**의 일반적 접근을 참고해 독립 작성했습니다. **공식 Superpowers Skill 원본을 복제·설치한 파일이 아닙니다.** 원문의 강제 작업 승인, Git 커밋, Browser 시각 보조, 추가 하위 에이전트 절차는 이 Skill에 포함하지 않습니다.

## 최우선 시작 조건

**응시자가 실제 과제 README를 직접 읽고 자신의 문제 이해와 목표를 정리하기 전에는 이 Skill을 실행하지 마세요.** 참가자가 별도로 브레인스토밍이나 대안 검토를 요청한 뒤에만 이 매뉴얼을 적용합니다. README를 AI가 먼저 요약하거나 문제 정의를 대신 확정하지 않습니다. 브레인스토밍은 참가자의 판단을 보완하는 수단입니다.

## 언제 사용?

- **참가자가 이미 이해한 뒤** README의 목표·입력·출력·예외·완료 기준 중 불명확한 부분을 검토해 달라고 요청할 때
- 업무 담당자의 설명을 해석하거나 여러 간단한 구현 방법을 고를 때
- 요구가 충분히 명확하다면 짧게 정리하고 즉시 구현으로 넘어갑니다.

## 6단계

1. **참가자 해석 먼저 확인:** 참가자가 이미 파악한 목표·업무 조건·예외·제출물부터 듣고, 실제 README와 다른 부분만 근거를 들어 확인합니다.
2. **사실과 가정 구분:** 문서에 적힌 조건과 내가 추정한 조건을 섞지 않습니다.
3. **중요 질문만:** 핵심 결과가 달라질 불명확성이 있으면 제공된 업무 담당자 채널에 질문하거나 참가자에게 질문을 제안합니다. 자명한 조건으로 무한히 질문하지 않습니다.
4. **최소 대안 비교:** 필요할 때만 2개 정도 대안을 비교합니다. 무조건 3개 아키텍처·대규모 기술을 제안하지 않습니다.
5. **선택 근거:** 과제 기준 충족, 단순성, 로컬 실행 가능성, 직접 검증 가능성을 우선합니다.
6. **구현·검증으로 연결:** 참가자가 결정한 방향과 남은 미확인 조건을 짧게 기록합니다. **참가자가 구현도 지시했다면** 가장 작은 작동 기능부터 진행하고, 중요한 미확정 요구·사용자 승인 필요 상황에서만 중단합니다.

**안전:** 공개 원본에 설치·Git 커밋·Browser 자동화 절차가 있더라도 이를 실행하지 않습니다. 일반 로컬 코드 테스트와 실제 결과 검증은 수행합니다.
