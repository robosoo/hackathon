# 데이터 오류·누락·중복 검증 — 데이터 품질 점검

이 문서는 공개 도구함이 직접 작성한 학습용 지침이며, 외부 DB 또는 클라우드 연결이 필요하지 않습니다.

## 순서
1. 입력 파일과 컬럼 설명을 읽고 행 단위(거래·Lot·이벤트 등)를 정합니다.
2. 식별자/키의 유일성, 중복 기록, 빈 값, 데이터 타입, 잘못된 날짜와 단위를 점검합니다.
3. 수치 집계라면 분자·분모를 명시하고 0/결측 분모를 어떻게 처리할지 정합니다.
4. 5% **초과**와 5% **이상**처럼 경계 연산자가 다른 경우를 별도로 검사합니다.
5. 명세에 없는 보정·삭제·추정 값은 마음대로 적용하지 않고 불확실성을 기록합니다.
6. 단순 합계·평균 또는 표본 일부를 독립 계산해 AI 출력과 대조합니다.
7. 관찰된 상관관계와 인과관계 주장에 필요한 근거를 구분합니다.

## 여러 파일 연결 검증 — 관련 과제에서만

두 개 이상의 CSV·표를 결합해야 한다면 다음을 **원본을 수정하지 않고** 확인합니다.

1. 파일마다 **한 행의 단위(grain)**를 정의합니다. 예: 주문 1건, 주문 상품 1개, 환불 요청 1건.
2. 식별자(예: `order_id`)와 참조 키를 확인하고 **1:1 / 1:N / N:1 / N:M** 중 어느 관계인지 실제 중복 빈도로 조사합니다. 이름이 같다는 이유만으로 1:1로 가정하지 않습니다.
3. 결합 전후 **행 수, 키 중복, 미매칭/고아 행, 다중 매칭**을 집계합니다. 예상치 못한 행 증가가 금액·수량의 중복 집계로 이어지는지 점검합니다.
4. 금액·수량·비율은 **원천 필드의 정의, 단위, 기간, 배송비·할인·부분 처리 포함 여부**를 확인한 뒤 계산합니다. 값이 서로 달라도 정의가 다르면 곧바로 오류라고 판단하지 않습니다.
5. 결합 유형(inner/left 등)과 집계 단위·계산식·제외 기준을 기록하고, 소량의 원본 사례로 **행 단위 대응과 전체 합계**를 각각 검산합니다. 합계만 일치한다고 결합이 올바르다고 확정하지 않습니다.
6. 모델을 학습·평가하는 과제라면 필드가 실제 판정 시점에 이용 가능했는지와 **사후 정보·중복 레코드의 학습/평가 누수**를 확인합니다.

문서로 확정된 규칙, 실제 관측된 불일치, 추정 원인을 별도로 보고합니다. 정합성 처리 정책이 불분명하면 참가자가 업무 담당자에게 확인할 질문을 제시하고, 근거 없이 삭제·보정·자동 거절하지 않습니다.
