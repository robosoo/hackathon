# 의사결정 기록 — 이유와 검증 근거를 남기기

이 Skill은 공개 참고용 **작업 방식**이며, 사전 시험 문제·정답·공식 평가표를 포함하지 않습니다. 사용자가 실제 과제 README를 직접 읽고 해결 방향을 판단한 다음에만 사용합니다. 기록이 과제 해결에 도움이 되지 않거나 기존 기록 문서가 있으면 새 파일을 강제로 만들지 않습니다.

## 언제 기록하나?

- 참가자가 중요한 업무 규칙, 예외 처리, 데이터 해석 또는 구현 범위를 **실제로 결정**했을 때
- 업무 담당자에게 확인한 답으로 처리 정책이 바뀌었을 때
- 중요한 검증이 끝나 결과·한계가 확인됐을 때
- 기존 가정을 철회하거나 처리 방식을 바꿨을 때

사소한 CLI 명령이나 AI의 제안을 모두 기록하지 않습니다. **AI가 제안한 내용은 사용자 결정으로 기록하지 않습니다.**

## 어디에 어떻게 기록하나?

시험 과제의 **허용된 로컬 작업공간**에서 기존 의사결정 기록이 있으면 이를 사용하고, 과제 지침과 충돌하지 않을 때만 예를 들어 `DECISIONS.md` 하나를 선택합니다. **복제한 공개 도구함 폴더 안에는 시험 기록을 만들지 않습니다. Git Push, 외부 전송·배포는 금지합니다.**

중요 판단 한 건당 간단한 표 한 줄로 기록합니다.

| 단계/시점 | 실제 결정 또는 보류 | 이유 | 근거(파일·조항·담당자 답변) | 검증 방법·관찰 결과 | 상태 |
| --- | --- | --- | --- | --- | --- |
| 예: 예외 확인 | 예: 규칙 충돌 건은 보류 | 판단 근거 불충분 | 실제 문서/답변 위치 | 예외 입력 테스트 결과 | 확인 / 미검증 |

- **확정된 사실 / 가정 / 미확인 / 충돌**을 구분합니다. 중요한 설계 선택에서 **실제로 검토하고 기각한 대안**이 있으면 이유를 짧게 남깁니다. 검토하지 않은 대안·실행하지 않은 실험을 지어내지 않습니다.
- 원본 정책·데이터를 지우거나 보정하지 않습니다. 기존 결정을 바꾸면 이전 판단과 새 판단을 구분하고 변경 이유를 남깁니다.
- 숫자·실행 성공 여부는 실제 근거가 있을 때만 기록합니다. 명령만 작성했다면 '미실행'입니다.
- 기록은 업무 담당자 답변과 테스트 결과의 간단한 참조이며, 채팅 전문이나 불필요한 개인정보를 옮기지 않습니다.

## 마지막 점검

제출 **확정 이전**, 기록에서 참가자가 직접 설명할 수 있어야 하는 주요 선택 이유, 대안, 검증 근거, 미해결 조건을 짧게 확인합니다. 실제 제출 요구 파일을 추가로 만든 것처럼 취급하지 않습니다.

**후속 서술형 등 AI 사용이 금지된 단계에서는 기록 작성·조회 지원·답변 작성도 중단합니다.** 사용자는 그 단계에 직접 답변합니다.
