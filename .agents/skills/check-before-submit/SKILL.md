# 제출 전 최종 검증 — 결과를 검증한 뒤 완료 판단

이 문서는 이 공개 저장소가 작성한 학습용 Skill입니다. 특정 외부 도구 설치를 전제로 하지 않습니다.

## 언제 사용?
- AI가 ‘완료’, ‘수정됨’, ‘테스트 통과’를 주장할 때
- 과제 제출 전에 파일·동작·예외조건을 점검할 때

## 순서
1. 과제 README에서 검증 가능한 완료 조건을 먼저 확인합니다.
2. 어떤 명령·입력·파일로 검증할지 설명하고, 허용된 작업 공간에서 실행합니다.
3. **실제로 관찰된 출력과 종료 상태**를 기록합니다. 결과가 없으면 ‘미검증’입니다.
4. 필수 정상 입력과 주요 경계·오류 입력을 구분합니다.
5. 실패나 누락이 있으면 수정 여부를 결정하고, 수정 후 같은 조건을 다시 검사합니다.
6. 마지막에 ‘확인한 성공 / 실패 / 미검증’을 별도로 보고합니다.

- 실제 테스트 명령·입력:
- 예상 결과 / 실제 결과:
- 실패·미검증:
- 제출 전 남은 일:

**안전:** 외부 배포·Git Push·별도 AI 연결 없이 수행합니다. 검증했다고 주장하기 전에 실제 증거를 확인합니다.
