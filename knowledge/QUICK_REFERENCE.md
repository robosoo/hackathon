# SW 비전공자를 위한 초간단 작업 용어·확인법

**선택형 위키:** 참가자가 용어 설명이나 검증 방법을 요청할 때만 읽습니다. 이 문서는 개발 환경 설치 명령서가 아니고, 시험에 실제로 필요한 작업만 해야 합니다.

| 용어 | 의미 | 직접 확인할 포인트 |
| --- | --- | --- |
| README | 과제의 요구·실행·제출 설명서 | 필수 입력·출력·예외·제출물 |
| 워크스페이스(Workspace) | AI와 참가자가 파일을 보는 작업 폴더 | 시험 과제 파일을 덮어쓰지 않았는가 |
| 터미널(Terminal) | 명령어를 입력하는 창 | **새 터미널 ≠ 새 AI 채팅** |
| 셸(Shell) | 터미널 안에서 명령을 해석·실행하는 프로그램 | Windows PowerShell, Bash 등 구분 |
| Node.js | 자바스크립트를 실행하는 런타임 | `node --version`은 **버전 조회**, 설치 아님 |
| npm | 자바스크립트 패키지/스크립트 실행 도구 | `package.json`에 정의된 작업부터 확인 |
| JSON / CSV | 기계가 처리하기 쉬운 구조화 자료 / 표 형식 | 자료형·필드·누락·중복·구분자 확인 |
| API | 프로그램끼리 기능/정보를 요청하는 규칙 | 입력·출력·실패 시 응답 확인 |
| localhost | 현재 시험 작업환경의 내부 주소를 뜻하는 관용적 이름 | 포트와 실행 상태 확인 |
| 로그(Log) | 실행 중 발생한 메시지 기록 | 실제 오류 문구·발생 조건·재현 여부 |
| 테스트(Test) | 기대하는 결과와 실제 결과를 비교 | **입력 → 기대 결과 → 관측 결과** |
| Git Push | 로컬 변경을 원격 저장소에 업로드 | **시험 산출물 Push 금지** |

## 과제를 읽을 때 참가자가 직접 판단할 것

1. 누가 무엇을 해결하려는가? (**목적**)
2. 입력과 결과 파일/화면은 무엇인가? (**입출력**)
3. 빠지면 실패하는 필수 요구와 제한은? (**필수 조건**)
4. 빈 값·중복·경계값·오류는? (**예외**)
5. 어떤 실제 테스트로 맞았다고 말할 수 있나? (**검증**)

## Codex에게 결과를 확인받는 방식

- “어떤 실제 입력으로 테스트했고 기대값과 관측값이 각각 무엇인지 알려줘.”
- “실패·미검증·실행하지 않은 테스트를 구분해줘.”
- “전문용어는 회로설계 검증에 비유해서 한 번 설명해줘.”

**주의:** 위 용어·예시는 학습용입니다. Codex가 제공하는 명령은 해당 파일·환경을 확인한 뒤 시험 규정상 허용되는 범위에서만 실행해야 합니다. 자동 브라우저 조작·외부 전송·기타 제한 우회는 하지 않습니다.
